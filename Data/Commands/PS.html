PowerShell 7 or Windows PowerShell 5.1

Two products share the name. Know which one you are running before you copy a command.

Current releasePowerShell 7.7 (Standard Term Support, November 2026, .NET 11)
Long Term SupportPowerShell 7.6 LTS (.NET 10), supported until November 2028
Out of supportPowerShell 7.4 and 7.5. Upgrade to 7.6 LTS or 7.7
Built into WindowsWindows PowerShell 5.1 (powershell.exe), maintained but gets no new features
Executablepwsh.exe for 7.x, powershell.exe for 5.1. Both can be installed side by side
Platforms7.x runs on Windows, Linux and macOS. 5.1 is Windows only

5.1 only: Get-EventLog, Clear-EventLog, Write-EventLog, Get-WmiObject and the other *-Wmi* cmdlets do not exist in PowerShell 7. Use Get-WinEvent and Get-CimInstance, which work in both. In 5.1, curl and wget are aliases for Invoke-WebRequest; in 7 they run the real curl.exe.

Compatibility: some Windows modules (for example ServerManager and GroupPolicy) load in PowerShell 7 through a hidden 5.1 session. They work, but results come back as deserialized objects without methods. If a module misbehaves in 7, run it in powershell.exe.

Pull fields out of events

Every event carries named fields in its XML. This turns failed logons into a table of user and source address.

Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4625; StartTime=(Get-Date).AddDays(-1)} | ForEach-Object {
    $eventData = ([xml]$_.ToXml()).Event.EventData.Data
    [pscustomobject]@{
        Time = $_.TimeCreated
        User = ($eventData | Where-Object Name -eq 'TargetUserName').'#text'
        Source = ($eventData | Where-Object Name -eq 'IpAddress').'#text'
        LogonType = ($eventData | Where-Object Name -eq 'LogonType').'#text'
    }
} | Group-Object Source | Sort-Object Count -Descending
