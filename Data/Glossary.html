Glossary

Common security terms explained in plain language, from access control to zero trust. Use the filter to find a word, or link straight to any term.

172 termsA to ZReviewed November 2026

A to B

Access, authentication, backups and the basic building blocks of attacks.

Access controlThe rules that decide who or what can use a resource and what they are allowed to do with it.
Account takeoverAn attacker gains control of a real user's account, usually with a stolen password, a stolen session cookie or a SIM swap.
Active Directory (AD)Microsoft's directory service for Windows domains. It stores users, computers and groups and handles sign in with Kerberos and NTLM, which makes it a top target in internal attacks.
Advanced persistent threat (APT)A skilled, well funded group, often state backed, that breaks in quietly and stays hidden for months to spy or steal.
Air gapA system kept physically separate from other networks. It raises the bar a lot, but USB drives and insiders can still cross it.
AllowlistA list of things that are explicitly permitted, such as approved apps or IP addresses. Anything not on the list is blocked.
AntivirusSoftware that finds and removes known malware using signatures and behavior rules. Modern products have grown into EDR.
Asymmetric encryptionEncryption with a key pair: a public key anyone can have and a private key only the owner keeps. Used for key exchange and digital signatures, for example RSA and elliptic curve cryptography.
Attack surfaceEvery place an attacker could try to get in: open ports, apps, APIs, accounts and people. Shrinking it is one of the cheapest defenses.
Attack vectorThe path or method an attacker uses to get in, such as a phishing email, a stolen password or an exposed remote desktop port.
AuthenticationProving who you are, with something you know (a password), something you have (a phone or key) or something you are (a fingerprint).
AuthorizationDeciding what an identity is allowed to do after it has been authenticated.
BackdoorA hidden way into a system that skips normal sign in, planted by an attacker or left behind by a developer.
BackupA copy of data you can restore from. The 3-2-1 rule: three copies, on two kinds of storage, one off site, with at least one offline or immutable so ransomware cannot reach it.
BlocklistA list of things that are explicitly denied, such as known bad domains or file hashes. Everything else is allowed, so it only stops what is already known.
Blue teamThe defenders who monitor systems, detect attacks and respond to them.
BotnetA network of infected computers, routers or cameras controlled by one operator and used for DDoS attacks, spam or credential stuffing.
Brute force attackTrying huge numbers of passwords or keys until one works. Long passwords, rate limits, lockouts and MFA stop it.
Buffer overflowA bug where a program writes more data into a block of memory than it can hold, overwriting what is next to it. It can crash the program or let an attacker run code.
Bug bountyA program where an organization pays researchers for finding and responsibly reporting vulnerabilities in its systems.
Business email compromise (BEC)Fraud where attackers take over or impersonate a business email account to trick staff into paying fake invoices or changing bank details. FBI reports rank it among the costliest cybercrimes.

C

Certificates, the CIA triad, vulnerability IDs and classic web attacks.

CertificateA digital document that ties a public key to an identity, such as a domain name, and is signed by a certificate authority so others can trust it.
Certificate authority (CA)A trusted organization or server that issues and signs certificates. Browsers and operating systems ship with a list of trusted root CAs.
Chain of custodyA record of who collected, handled and stored each piece of evidence and when, so it holds up in court or an internal review.
CIA triadThe three goals of security: confidentiality (only the right people see data), integrity (data is not changed without permission) and availability (systems work when they are needed).
CIS ControlsA prioritized set of 18 security safeguards from the Center for Internet Security, split into Implementation Groups 1 to 3. Group 1 is the basic hygiene every organization should have.
ClickjackingTricking a user into clicking something hidden under a harmless looking page, usually with an invisible frame. Sites block it with the frame-ancestors policy or the X-Frame-Options header.
Cloud security posture management (CSPM)Tools that scan cloud accounts for risky settings, such as public storage buckets, missing logging or overly broad IAM roles.
Command and control (C2)The channel attackers use to send commands to compromised machines and receive stolen data, often hidden in normal looking HTTPS or DNS traffic.
ContainmentThe incident response step that stops an attack from spreading, for example isolating a host or disabling an account, while keeping the evidence.
Credential stuffingLogging in with user name and password pairs leaked from another site, betting that people reuse passwords. Unique passwords and MFA stop it.
Cross-site request forgery (CSRF)Tricks a signed in user's browser into sending an unwanted request to a site that trusts it, such as changing the account email. Anti CSRF tokens and SameSite cookies prevent it.
Cross-site scripting (XSS)Injecting a script into a web page so it runs in other visitors' browsers, where it can steal sessions or act as them. Output encoding and a Content Security Policy prevent it.
CVECommon Vulnerabilities and Exposures: a unique public ID for one specific known vulnerability, for example CVE-2021-44228 (Log4Shell).
CVSSCommon Vulnerability Scoring System: rates how severe a vulnerability is from 0.0 to 10.0, with version 4.0 current. Severity is not the same as your risk, so also check whether it is exploited and exposed.
CWECommon Weakness Enumeration: a catalog of the kinds of mistakes that cause vulnerabilities, such as CWE-79 for XSS. A CVE is one bug, a CWE is the type of bug.
Cyber Kill ChainLockheed Martin's seven stage model of an intrusion, from reconnaissance to actions on objectives. Breaking any link stops the attack.

D to E

Denial of service, email protection, encryption and endpoint defense.

Data breachAn incident where data is accessed or disclosed without permission. Many laws require telling regulators and affected people within a set deadline.
Data loss prevention (DLP)Tools and rules that spot sensitive data and block it from leaving through email, uploads, USB drives or cloud apps.
DDoSDistributed denial of service: flooding a service from many machines at once, often a botnet, so real users cannot reach it.
Defense in depthLayering several independent controls, such as MFA, EDR, segmentation and backups, so one failure does not mean a breach.
Denial of service (DoS)Any attack that makes a system unavailable, either by flooding it or by crashing it with a crafted input.
Digital forensicsCollecting, preserving and analyzing digital evidence in a way others can trust and repeat. Often paired with incident response as DFIR.
Digital signatureA value made with a private key that proves who signed some data and that it has not changed since. Anyone with the matching public key can check it.
Disk imageA bit for bit copy of a storage device, verified with a hash, so investigators work on the copy and never on the original.
DMARC, SPF and DKIMEmail checks that work together: SPF lists which servers may send for a domain, DKIM signs each message, and DMARC tells receivers to quarantine or reject mail that fails, which stops direct spoofing of your domain.
DMZA network zone between the internet and the internal network for public facing servers, so a break in there does not lead straight to internal systems.
DNSDomain Name System: turns names like example.com into IP addresses. Attackers abuse it for lookalike domains, tunneling and C2, so DNS logs are valuable evidence.
DNS spoofingFeeding false DNS answers, also called cache poisoning, so victims are sent to an attacker's server. DNSSEC and encrypted DNS help prevent it.
Drive-by downloadMalware delivered just by visiting a malicious or hacked web page, usually through a browser flaw. Keeping the browser updated is the main defense.
EDREndpoint detection and response: an agent on laptops and servers that records activity, detects suspicious behavior and lets responders isolate and investigate hosts.
EncryptionTurning readable data (plaintext) into scrambled data (ciphertext) that only someone with the right key can turn back.
Encryption at rest and in transitData at rest is stored, data in transit is moving over a network. Protect both, for example BitLocker or FileVault on disks and TLS on the wire.
End-to-end encryption (E2EE)Only the sender and the receiver can read the messages, not the service that carries them. Signal and WhatsApp use it by default.
EndpointAny device that connects to a network: laptops, phones, servers and virtual machines.
EradicationThe incident response step that removes the attacker completely: malware, persistence, rogue accounts, and the hole they came in through.
ExfiltrationMoving stolen data out of an organization, often over HTTPS, cloud storage services or DNS so it blends in.
ExploitCode or a technique that takes advantage of a vulnerability to make a system do something it should not.

F to H

Detection accuracy, firewalls, hashing and hardening.

False negativeA real attack that security tools missed. More dangerous than a false positive, because nobody goes looking.
False positiveAn alert for something harmless. Too many of them cause alert fatigue, and real attacks get ignored.
File integrity monitoring (FIM)Watches important files and settings for unexpected changes, usually by comparing hashes against a known good baseline.
Fileless malwareMalware that runs mostly in memory or through built-in tools such as PowerShell and WMI, leaving few files on disk to scan.
FirewallFilters network traffic with rules about source, destination, port and protocol. Next generation firewalls also understand applications and users.
FuzzingFeeding a program huge amounts of random or malformed input to find crashes and hidden bugs.
GDPRThe EU General Data Protection Regulation. It sets rules for handling personal data of people in the EU and requires reporting qualifying breaches to the regulator within 72 hours.
Golden ticketA forged Kerberos ticket made with the hash of the domain's KRBTGT account, giving access to anything in the domain. Recovery means resetting the KRBTGT password twice.
HacktivistAn attacker driven by a political or social cause, often using DDoS attacks, defacements and data leaks.
HardeningShrinking the attack surface of a system by removing unneeded software, closing ports, changing defaults and applying secure settings.
HashingA one way function that turns any input into a fixed length fingerprint, such as SHA-256. The same input always gives the same hash, and a tiny change gives a completely different one.
HoneypotA decoy system, file or account that has no real use, so any interaction with it is a strong sign of an attacker.
HTTPSHTTP over TLS. It encrypts traffic between the browser and the site and proves the site's name, but the padlock does not mean the site is honest.

I to K

Identity, intrusion detection, incident response and Kerberos.

Identity and access management (IAM)The people, processes and tools that create identities, grant them access and remove it when it is no longer needed.
IncidentA security event that harms or threatens the confidentiality, integrity or availability of systems or data and needs a response.
Incident response (IR)The planned way an organization handles incidents. The classic phases are preparation, detection and analysis, containment, eradication and recovery, and lessons learned. NIST SP 800-61 Rev. 3 now maps them to the NIST CSF 2.0 functions.
Indicator of attack (IOA)Behavior that shows an attack in progress whatever tool is used, such as Word starting PowerShell or a process reading LSASS memory.
Indicator of compromise (IOC)Evidence that a system may be compromised, such as a known malicious file hash, IP address, domain or registry key.
InfostealerMalware that grabs saved passwords, browser cookies, crypto wallets and tokens and sends them to the attacker. A common first step of account takeover.
Initial access brokerA criminal who breaks into networks and sells that access to others, such as ransomware gangs.
InjectionA family of attacks where untrusted input is treated as code or a command, such as SQL, OS command or LDAP injection.
Insider threatRisk from people who already have legitimate access, whether they are malicious, careless or tricked by someone else.
Intrusion detection system (IDS)Watches network or host activity and raises alerts on suspicious patterns, without blocking anything. Snort and Suricata are well known examples.
Intrusion prevention system (IPS)Like an IDS, but it sits in the traffic path and can block malicious traffic as well as alert on it.
JSON Web Token (JWT)A compact signed token that carries claims such as a user ID, common in APIs and OAuth. Anyone can read its contents, so never put secrets in it, and always verify the signature and algorithm.
KerberoastingRequesting Kerberos service tickets for accounts with a service principal name and cracking them offline to recover service account passwords. Long random passwords and managed service accounts defeat it.
KerberosThe ticket based sign in protocol used by Active Directory. Users get a ticket granting ticket from the domain controller, then service tickets, so passwords never cross the network.
KEVCISA's Known Exploited Vulnerabilities catalog: CVEs confirmed to be exploited in real attacks. A great list to patch first.
KeyloggerSoftware or a small device that records keystrokes to capture passwords and messages.

L to N

Moving through networks, malware, MFA and the big frameworks.

Lateral movementMoving from the first compromised machine to others in the network, using stolen credentials, remote admin tools or exploits.
Least privilegeGive every user, service and app only the access it needs, and only for as long as it needs it.
Living off the land (LOTL)Attacking with tools that are already on the system, such as PowerShell, certutil or WMI, to blend in with normal admin work. These tools are often called LOLBins.
LoggingRecording events such as sign ins, process starts and configuration changes. Logs sent to a central place like a SIEM survive even if an attacker wipes the host.
MalwareAny software built to cause harm, including viruses, worms, trojans, ransomware, spyware and infostealers.
Man in the middle (MITM)An attacker secretly sits between two parties to read or change their traffic, also called adversary in the middle. Phishing kits now proxy real login pages to steal session cookies and bypass MFA, which phishing resistant MFA stops.
Managed detection and response (MDR)An outside provider that watches your environment around the clock and investigates and responds to threats for you.
Memory forensicsAnalyzing a capture of RAM to find running processes, network connections, injected code and keys that never touch the disk. Volatility is a common tool.
Multi-factor authentication (MFA)Signing in with two or more different kinds of proof, such as a password plus an authenticator app or security key. SMS codes beat nothing, but app, hardware key and passkey options are much stronger.
MFA fatigueSpamming a user with push sign in requests until they approve one just to make it stop. Number matching blocks most of it.
MITRE ATT&CKA free knowledge base of real attacker tactics and techniques, each with an ID such as T1059 (Command and Scripting Interpreter). Teams use it to map detections and find gaps.
Network segmentationSplitting a network into zones with controlled traffic between them, so an attacker in one zone cannot freely reach the others.
NIST CSFThe NIST Cybersecurity Framework. Version 2.0 (2024) has six functions: Govern, Identify, Protect, Detect, Respond and Recover, used to plan and measure a security program.
NTLMAn older Microsoft challenge and response sign in protocol. It is open to relay and pass the hash attacks, and Microsoft has deprecated it in favor of Kerberos.

O to P

Modern sign in standards, passwords, phishing and privilege.

OAuth 2.0A standard that lets an app get limited access to your data on another service with a token, without ever seeing your password. Malicious apps that trick users into granting access (consent phishing) are a growing attack.
OpenID Connect (OIDC)An identity layer on top of OAuth 2.0 that tells an app who signed in, using an ID token. It powers most "Sign in with" buttons.
Order of volatilityCollect the most short lived evidence first: CPU and memory, then network connections and running processes, then disk, then remote logs and backups (RFC 3227).
OSINTOpen source intelligence: information gathered from public sources such as websites, social media, DNS records and leaked data.
OWASP Top 10A list of the most critical web application security risks from the OWASP Foundation. Broken Access Control tops the 2025 edition.
Pass the hashSigning in with a stolen NTLM password hash instead of the password itself. Credential Guard, LAPS and limiting where admins sign in reduce it.
PasskeyA phishing resistant replacement for passwords built on FIDO2 and WebAuthn. Your device keeps a private key, unlocks it with your face, fingerprint or PIN, and only signs in to the real site it was made for.
Password hashingStoring passwords as slow, salted hashes so a stolen database is hard to crack. Use Argon2id, scrypt, bcrypt or PBKDF2, never fast hashes like MD5 or plain SHA-256.
Password managerAn app that creates and stores a unique strong password for every account, protected by one strong master password and MFA.
Password sprayingTrying a few very common passwords against many accounts, staying under the lockout limit for each one.
PatchAn update that fixes bugs or vulnerabilities. Patch management is the process of testing and rolling patches out quickly, starting with exploited ones.
PayloadThe part of an attack that does the real work once delivered, such as a reverse shell, an infostealer or ransomware.
Penetration testAn authorized, scoped attack simulation that finds and proves exploitable weaknesses and ends with a report on how to fix them.
PersistenceTechniques attackers use to keep access across reboots and password changes, such as scheduled tasks, services, Run keys or extra accounts.
PhishingFake messages that trick people into clicking a link, opening an attachment or typing in their password. It is still the most common way attacks begin.
Public key infrastructure (PKI)The certificate authorities, certificates, policies and revocation systems that let people and machines trust public keys.
PlaybookA step by step guide for handling one type of incident, such as phishing or ransomware. SOAR tools can automate parts of it.
Privilege escalationGaining more permissions than you were given, either vertically (user to admin) or horizontally (one user to another user's data).
Purple teamRed and blue teams working side by side, running attacks and tuning detections together in real time.

Q to S

Ransomware, risk, security operations and many common attacks.

QuishingPhishing with QR codes, in emails, letters or stickers, that leads to a fake login page and slips past email link scanners.
RansomwareMalware that encrypts files and demands payment for the key. Most gangs now steal data first and threaten to leak it too (double extortion).
RecoveryThe incident response step that restores systems from clean backups and returns to normal operations while watching closely for the attacker's return.
Red teamA team that imitates real attackers over a longer engagement to test how well the organization detects and responds, not only to find bugs.
Remote code execution (RCE)A vulnerability that lets an attacker run their own code on a system over the network. Almost always rated critical.
Reverse shellA command shell where the compromised machine connects out to the attacker, which gets past firewalls that only block incoming connections.
RiskThe chance that a threat exploits a vulnerability, combined with the damage if it does. Risk can be reduced, transferred (for example with insurance), avoided or accepted.
RootkitMalware that hides itself and other malicious activity by tampering with the operating system, sometimes at kernel or firmware level.
SaltingAdding a unique random value to each password before hashing, so identical passwords get different hashes and precomputed rainbow tables are useless.
SAMLSecurity Assertion Markup Language: an XML standard where an identity provider sends signed statements about a user to apps for single sign on. Common in enterprises.
SandboxAn isolated environment for running untrusted code or opening suspicious files safely, also used to watch what malware does.
SBOMSoftware bill of materials: a list of every component and library inside a piece of software, so you can quickly tell whether a new vulnerability affects you.
Secure BootA UEFI feature that only lets signed boot loaders and operating systems start, which blocks most bootkits.
Session hijackingStealing a valid session cookie or token to act as a signed in user without needing their password or MFA.
SIEMSecurity information and event management: collects logs from across the organization, links related events and raises alerts. Examples are Splunk, Microsoft Sentinel and Elastic Security.
SIM swappingConvincing a mobile carrier to move a victim's phone number to an attacker's SIM card to receive their SMS codes and calls.
SmishingPhishing over SMS or chat apps, often fake delivery, toll or bank alerts.
SOARSecurity orchestration, automation and response: runs playbooks that enrich alerts and take actions automatically, such as blocking an IP or disabling an account.
SOCSecurity operations center: the team, often working around the clock, that monitors alerts, investigates and responds to incidents.
Social engineeringManipulating people rather than technology, using trust, urgency, fear or curiosity to get them to hand over access.
Spear phishingPhishing aimed at a specific person or team, using real details about them to look believable. Aimed at executives, it is called whaling.
SpoofingFaking an identity, such as an email sender, caller ID, IP address or MAC address, to look trusted.
SQL injectionSlipping SQL code into an input that is built into a database query, letting an attacker read or change data. Parameterized queries prevent it.
Single sign on (SSO)One sign in at an identity provider gives access to many apps. Easier to protect and audit, but that one account becomes very valuable, so guard it with strong MFA.
Server-side request forgery (SSRF)Tricks a server into sending requests to places the attacker chooses, such as internal services or the cloud metadata address 169.254.169.254.
Supply chain attackBreaking into a trusted vendor, software update or open source package to reach its customers, as in SolarWinds or the XZ Utils backdoor.
Symmetric encryptionOne shared secret key both encrypts and decrypts, which is fast for large amounts of data, for example AES-256. The hard part is sharing the key safely.

T to Z

Threats, TLS, vulnerabilities and zero trust.

Tabletop exerciseA discussion based drill where a team talks through a realistic incident to test its plan, roles and decisions before a real one happens.
ThreatAnything that could cause harm by exploiting a vulnerability, such as a criminal group, a careless insider or a power outage.
Threat actorThe person or group behind an attack: cybercriminals, nation states, hacktivists or insiders.
Threat huntingActively searching for attackers that slipped past alerts, starting from a hypothesis and digging through telemetry.
Threat intelligenceAnalyzed information about threat actors, their methods and their indicators, used to guide decisions and detections.
Threat modelingWorking out what you are building, what can go wrong and what to do about it, before attackers find out. STRIDE is a popular method.
Timeline analysisPutting events from logs, file system timestamps and other artifacts in time order to rebuild what happened during an incident.
TLSTransport Layer Security: encrypts and authenticates network connections such as HTTPS. Use TLS 1.3 or 1.2; SSL and TLS 1.0 and 1.1 are retired.
TokenData that proves you are signed in or allowed to do something, such as a session cookie, an OAuth access token or a hardware key. A stolen token can bypass passwords and MFA.
TriageQuickly sorting alerts or incidents by severity and gathering key facts, so the most important ones get attention first.
TrojanMalware disguised as something useful, such as a cracked game, a fake update or a browser extension.
TTPsTactics, techniques and procedures: how an attacker works. They are harder to change than IOCs, so detections built on TTPs last longer.
Two-factor authentication (2FA)MFA with exactly two factors, usually a password plus a code, push approval or security key.
VishingVoice phishing over phone calls, often posing as the IT help desk or a bank, and sometimes using AI cloned voices.
VPNVirtual private network: an encrypted tunnel between a device and a network. Company VPN appliances are a favorite target and need fast patching.
VulnerabilityA weakness in software, hardware, settings or a process that an attacker could exploit.
Vulnerability scanningAutomatically checking systems for known vulnerabilities and weak settings, for example with Nessus, OpenVAS or Nuclei.
Web application firewall (WAF)Filters HTTP traffic to block attacks such as SQL injection and XSS before they reach the app. It helps, but it does not replace fixing the code.
Watering hole attackHacking a website that a target group often visits, so the visitors get infected.
WormMalware that spreads on its own from machine to machine without anyone clicking anything, such as WannaCry.
Write blockerA hardware or software tool that lets an investigator read a drive without changing a single bit on it.
XDRExtended detection and response: combines data from endpoints, email, identity, cloud and network into one place to detect and respond to attacks.
Zero click exploitAn exploit that needs no action from the victim at all, often delivered through a message to a phone app. Keep devices updated and consider Lockdown Mode if you are high risk.
Zero dayA vulnerability that the vendor does not know about or has not fixed yet, so defenders have had zero days to patch it.
Zero trustA model that never trusts a request just because it comes from inside the network. Every access is checked against identity, device health and context, and given least privilege (NIST SP 800-207).
