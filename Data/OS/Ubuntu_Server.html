Ubuntu Server Security Paths

High value files and folders on Ubuntu Server 26.04 LTS and 24.04 LTS: where secrets sit, where attackers persist, where the evidence is, and how to check and harden a host.

Overview

Key facts for the releases you will meet in production today.

Current releaseUbuntu 26.04 LTS (Resolute Raccoon, point release 26.04.1) with Linux 7.0. Previous LTS: 24.04 LTS (Noble Numbat) with Linux 6.8 and HWE kernels. Latest interim: 26.10 (Stonking Stingray), supported to July 2027.
Support status26.04: standard security updates to 2031, Ubuntu Pro ESM to 2036, Legacy add-on to 2041. 24.04: standard to 2029, Pro to 2034, Legacy to 2039. 22.04: standard to 2027. Ubuntu Pro is free for personal use on up to 5 machines.
File systemext4 on LVM by default in the server installer. ZFS, Btrfs, XFS and LUKS encryption are optional. Merged /usr: /bin, /sbin and /lib are symlinks into /usr.
Built-in security featuresAppArmor in enforce mode, unattended security upgrades, UFW (installed but inactive), yescrypt password hashes, restricted unprivileged user namespaces, Livepatch with Ubuntu Pro. 26.04 adds sudo-rs as the default sudo, OpenSSH 10.2 with hybrid post-quantum key exchange and chrony with NTS.
Where logs livesystemd journal in /var/log/journal/ plus rsyslog text files in /var/log/ (auth.log, syslog, kern.log). auditd writes to /var/log/audit/ once installed. Minimal images may ship without rsyslog.
Init and packagessystemd (259 on 26.04, the last release that runs SysV init scripts), APT with deb822 sources (apt-key removed in 26.04), snapd for snaps such as LXD.

Note: Paths are for a default install. Use them to defend your own servers or on systems you are authorized to test.

Hardening Checklist

Baseline settings for an internet facing Ubuntu Server.

  • Run a supported LTS (26.04 or 24.04). Attach Ubuntu Pro with pro attach for ESM on universe packages and Livepatch.
  • Keep unattended-upgrades on and check /var/log/unattended-upgrades/. Reboot for kernel updates when Livepatch is not in use.
  • SSH: keys only. Put PasswordAuthentication no and PermitRootLogin no in a low numbered drop-in such as /etc/ssh/sshd_config.d/10-hardening.conf, since the first value wins, then confirm with sshd -T.
  • After changing the SSH port on a socket activated system, run systemctl daemon-reload and systemctl restart ssh.socket, and keep a session open until you have tested a new login.
  • Enable UFW with default deny incoming: ufw allow OpenSSH first, then ufw enable. Restrict egress on servers that do not need it.
  • Keep AppArmor in enforce mode and add local overrides instead of disabling profiles.
  • Install auditd and watch /etc/shadow, /etc/sudoers*, /etc/ssh/, cron folders, systemd unit folders and /etc/ld.so.preload.
  • Forward logs off the host (rsyslog or systemd-journal-remote) so an intruder cannot erase the only copy.
  • Keep sudo, docker and lxd groups minimal. Never expose the Docker API on TCP without mutual TLS.
  • Remove or disable unused services with systemctl disable --now and purge unneeded packages.
  • Check permissions: /etc/shadow 640 root:shadow, netplan files 600, home folders 750.
  • Delete or protect provisioning leftovers: cloud-init user data, /var/log/installer/autoinstall-user-data and old backups.
  • Mount /tmp and /dev/shm with nodev,nosuid,noexec where applications allow it.
  • Keep the kernel hardening defaults, including the unprivileged user namespace restriction, and use Secure Boot so only signed modules load.
  • Record a baseline of SUID files, enabled units, timers, listening ports and package list, and diff it on a schedule.
  • Use full disk encryption with LUKS on hardware that could be stolen, and encrypt off-site backups.
