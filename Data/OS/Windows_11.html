System Files

Windows 11 System Files

The files, registry keys and logs that matter most on a Windows 11 workstation: where secrets live, where attackers persist, and where defenders find the evidence.

Windows 11 26H2103 pathsReviewed November 2026
All systems Windows 11 Windows Server macOS iOS Android Ubuntu Server Kali Linux

Overview

Key facts about the current Windows 11 release and where its security data lives.

Current releaseWindows 11 version 26H2 (2026 Update), generally available since September 29, 2026 as an enablement package on top of 24H2 and 25H2. Version 26H1 is a separate release that ships only on select new devices.
Support status26H2: 24 months for Home and Pro, 36 months for Enterprise and Education. 25H2 Home and Pro: until October 12, 2027. 24H2 Home and Pro ended October 13, 2026. Windows 10 ended October 14, 2025; consumer ESU was extended to October 12, 2027 (Windows 10 22H2), commercial ESU runs to October 2028.
File systemNTFS on the system volume, ReFS for Dev Drive volumes, FAT32 and exFAT for removable media. The EFI System Partition is FAT32.
Built-in security featuresTPM 2.0 and Secure Boot required, VBS and memory integrity (HVCI), Credential Guard (on by default on qualifying Enterprise and Education devices), LSA protection, Microsoft Defender Antivirus, Smart App Control, BitLocker and device encryption, Windows Hello and passkeys, Windows LAPS, Administrator protection (policy enabled), built-in Sysmon (off by default).
Where logs liveC:\Windows\System32\winevt\Logs\*.evtx for event logs, C:\ProgramData\Microsoft\Windows Defender\ for Defender, C:\Windows\Logs\ for servicing logs.
Registry hivesMachine hives in C:\Windows\System32\config\, user hives in NTUSER.DAT and UsrClass.dat inside each profile.

Note: paths use environment variables where Windows does: %APPDATA% is C:\Users\<User>\AppData\Roaming and %LOCALAPPDATA% is C:\Users\<User>\AppData\Local. Most files below are locked while Windows runs and need admin rights, a shadow copy or an offline image to read.

Credentials and Secrets

Account databases, LSA secrets, DPAPI keys and saved credentials, the first targets after local admin.

PathContentsWhy it mattersRisk
C:\Windows\System32\config\SAMLocal account database with NT hashesWith the SYSTEM hive it gives every local hash for cracking or pass the hash. Copies are made with reg save or from shadow copies, which defenders should alert on.Critical
C:\Windows\System32\config\SYSTEMSystem hive, including the boot keyThe boot key decrypts SAM and LSA secrets, so SAM and SECURITY are useless offline without it.Critical
C:\Windows\System32\config\SECURITYLSA policy, LSA secrets and cached domain logonsHolds service account passwords, the machine account secret and DPAPI_SYSTEM.Critical
HKLM\SECURITY\Policy\SecretsLSA secrets: $MACHINE.ACC, DPAPI_SYSTEM, _SC_<service>, DefaultPasswordPlain text service passwords and the key that unlocks system DPAPI. Only SYSTEM can read the key.Critical
HKLM\SECURITY\CacheCached domain credentials (DCC2, 10 by default)Lets users log on without a domain controller. Hashes are slow to crack but weak passwords fall.High
lsass.exe process memoryCredentials of logged on users: NT hashes, Kerberos tickets, sometimes clear textMemory dumps (procdump, comsvcs.dll MiniDump, Task Manager) are a top attack technique. LSA protection and Credential Guard (secrets moved to LsaIso.exe) block most of it.Critical
%APPDATA%\Microsoft\Protect\<SID>\User DPAPI master keys, protected by the user password and, on domain machines, the domain backup keyUnlocks everything the user protected with DPAPI: browser keys, Credential Manager, Wi-Fi in user context, app secrets.Critical
C:\Windows\System32\Microsoft\Protect\S-1-5-18\System DPAPI master keys (and the User subfolder)Decrypted with the DPAPI_SYSTEM LSA secret. Protects Wi-Fi keys, scheduled task credentials and machine certificates.High
%LOCALAPPDATA%\Microsoft\Credentials\ and %APPDATA%\Microsoft\Credentials\Credential Manager blobsSaved RDP, SMB and app passwords. Decrypt with the user DPAPI master key.High
%LOCALAPPDATA%\Microsoft\Vault\ and C:\ProgramData\Microsoft\Vault\Windows Vault (web credentials and system vault)Old Internet Explorer and Edge web passwords and some app tokens, DPAPI protected.Medium
%APPDATA%\Microsoft\Crypto\ and C:\ProgramData\Microsoft\Crypto\RSA\MachineKeys\User and machine private keys for certificatesExported keys allow certificate based authentication as the user or machine, including VPN and Wi-Fi EAP-TLS.High
C:\Windows\Panther\Unattend.xmlSetup answer file (also C:\Windows\Panther\Unattend\ and C:\Windows\System32\Sysprep\)Often keeps the local admin password in base64. A classic privilege escalation find on imaged machines.Critical
HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon (DefaultPassword)Auto logon user name and, if set the old way, a clear text passwordReadable by any local user when stored here. Sysinternals Autologon stores it as an LSA secret instead.High
C:\Windows\ServiceProfiles\LocalService\AppData\Local\Microsoft\Ngc\Windows Hello key containers (PIN, face, fingerprint)Keys are bound to the TPM, so copying the folder is not enough. Tampering here breaks Hello sign in. SYSTEM only.Medium
\\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy<N>\Windows\System32\config\Registry hives inside Volume Shadow CopiesLets an admin, or a user on badly configured ACLs (HiveNightmare, CVE-2021-36934), copy SAM and SYSTEM without touching the live files.High

HKLM\SOFTWARE\Microsoft\Policies\LAPSWindows LAPS policy (backup target, rotation, complexity)Shows whether the local admin password is unique and rotated, and whether it is backed up to Entra ID or AD.Low

Places that run code at boot or logon. Check them with Autoruns before anything else.

HKCU\Software\Microsoft\Windows\CurrentVersion\Run and RunOncePer user logon autorunsNo admin needed, so it is the first choice for commodity malware and infostealers.High
C:\ProgramData\Microsoft\Windows\Start Menu\Programs\StartUp\All users Startup folderShortcuts and scripts run at every logon.High

C:\Windows\System32\wbem\Repository\WMI repository (OBJECTS.DATA) with event filters, consumers and bindingsFileless persistence that survives reboots. Watch WMI-Activity Operational event 5861 and Sysmon events 19 to 21.High

Hardening Checklist

Settings that close the paths above on a Windows 11 fleet.

  • Stay on a supported release (25H2 or 26H2) and install monthly cumulative updates.
  • Keep Secure Boot on, confirm the 2023 Secure Boot certificates are applied (the 2011 certificates expired in June and October 2026), and keep TPM 2.0 enabled.
  • Turn on memory integrity (HVCI), Credential Guard and LSA protection, and keep the vulnerable driver blocklist enabled.
  • Use standard user accounts day to day and enable Administrator protection where supported.
  • Deploy Windows LAPS so every local admin password is unique and rotated, backed up to Entra ID or AD.
  • Encrypt with BitLocker using TPM plus PIN on laptops, and escrow recovery keys to Entra ID or AD with restricted read access.
  • Keep Defender real time protection, cloud protection and tamper protection on; enable attack surface reduction rules, including blocking credential theft from LSASS.
  • Use App Control for Business or Smart App Control to stop unknown binaries.
  • Enable PowerShell script block logging, command line process auditing (4688) and Sysmon, and forward logs to a SIEM.
  • Increase Security.evtx size from the default so evidence is not overwritten in hours.
  • Remove leftover Unattend.xml files and never store auto logon passwords in the registry.
  • Require SMB signing (on by default since 24H2), keep SMB1 removed, and block NTLM where possible.
  • Disable RDP unless needed; when used, require Network Level Authentication and restrict it with the firewall.
  • Prefer Windows Hello for Business and passkeys over passwords, and discourage saving passwords in the browser.
  • Leave Recall off on managed devices unless policy allows it, and exclude sensitive apps and sites if it is used.
