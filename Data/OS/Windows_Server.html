System Files

Windows Server System Files

The files, registry keys, directory objects and logs that matter most on Windows Server: domain controllers, role servers and the secrets that make them tier 0.

Windows Server 2025116 pathsReviewed November 2026

Overview

Key facts about the current Windows Server release and the versions still in the field.

Current releaseWindows Server 2025 (LTSC, build 26100), generally available since November 1, 2024. Windows Server 2028 was announced at Ignite in November 2026 and is in preview only.
Support status2025: mainstream to November 13, 2029, extended to November 14, 2034. 2022: mainstream ended October 13, 2026, extended to October 14, 2031. 2019: extended to January 9, 2029. 2016: extended support ends January 12, 2027. 2012 and 2012 R2: ESU ended October 2026.
File systemNTFS for the system volume, ReFS for data, Hyper-V and Storage Spaces Direct volumes.
Built-in security featuresCredential Guard on by default on qualifying servers that are not domain controllers, LSA protection, Secured-core server, SMB signing required for outbound connections, SMB over QUIC in all editions, NTLMv1 removed, Windows LAPS with automatic account management, delegated managed service accounts (dMSA), hotpatching through Azure Arc, Microsoft Defender Antivirus, built-in Sysmon (off by default).
Where logs liveC:\Windows\System32\winevt\Logs\*.evtx for event logs, plus role logs: C:\inetpub\logs\LogFiles\ (IIS), C:\Windows\System32\dns\ (DNS), C:\Windows\System32\dhcp\ (DHCP), C:\Windows\debug\ (Netlogon).
Install optionsServer Core (default, no desktop) or Desktop Experience. Manage remotely with PowerShell, Windows Admin Center or Server Manager.

Note: a domain controller, its backups, its virtual disks and any server that can control it (AD CS, Entra Connect, hypervisors, backup servers) are tier 0. Treat a copy of any of them as a copy of the whole domain.

Hardening Checklist

Settings that close the paths above on servers and domain controllers.

  • Run a supported version (2025, 2022 or 2019) and plan the move off Windows Server 2016 before January 12, 2027.
  • Use Server Core where possible and install only the roles the server needs.
  • Separate admin tiers: domain admins log on only to DCs and tier 0 systems, from privileged access workstations, never to member servers or the web.
  • Put admin accounts in Protected Users and mark them as sensitive and not delegable.
  • Replace service account passwords with gMSA or dMSA accounts, and restrict who can create dMSAs.
  • Deploy Windows LAPS on every server, and on DCs back up the DSRM password with it.
  • Turn on Credential Guard and LSA protection on member servers, and memory integrity everywhere supported.
  • Require LDAP signing and channel binding, and finish the move off RC4 for Kerberos as described in KB5073381.
  • Rotate the krbtgt password regularly and twice in a row after a suspected compromise.
  • Remove any cpassword from SYSVOL and audit GPO edit rights.
  • Audit AD CS templates and CA permissions for ESC misconfigurations, and protect the CA key with an HSM where possible.
  • Disable the Print Spooler on DCs and on servers that do not print.
  • Require SMB signing, keep SMB1 removed, and reduce NTLM use with auditing before blocking.
  • Require NLA for RDP, limit RDP and WinRM to admin networks, and put RD Gateway or RD Web behind MFA.
  • Enable advanced audit policy, command line logging, PowerShell script block logging and Sysmon, and forward logs to a SIEM.
  • Keep Defender (or your EDR) on with tamper protection, and review exclusions added by role installers.
  • Protect backups and virtual disks of tier 0 servers like the DCs themselves, and keep an offline or immutable copy.
  • Confirm the 2023 Secure Boot certificates are applied on physical hosts and Hyper-V guests.
  • Plan a WSUS replacement (Windows Update for Business, Intune or Azure Update Manager) since WSUS is deprecated.
