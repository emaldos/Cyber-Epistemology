Cloud Security

Administration, auditing and hardening for AWS, Microsoft Azure and Google Cloud accounts. Check who you are, who can do what, what the logs say and which settings leave the door open.

AWS, Azure and GCP98 entriesReviewed November 2026

Overview

The ideas that shape every cloud review, whatever the provider.

Shared responsibilityThe provider secures the physical data centers, hardware and managed service internals. You secure identities, permissions, data, network rules, guest operating systems and configuration. Most cloud breaches come from the customer side of that line.
Identity is the perimeterEvery API call is authenticated, so a stolen access key, token or session cookie is as good as being inside. Protect accounts with MFA and short-lived credentials before worrying about firewalls.
Control plane and data planeThe control plane manages resources (create a VM, change a role). The data plane touches the content (read an object, query a database). Control plane activity is logged by default; data plane logging is often off and must be enabled.
Resource hierarchyAWS: organization, organizational units, accounts. Azure: Microsoft Entra ID tenant, management groups, subscriptions, resource groups. GCP: organization, folders, projects. Permissions granted high in the tree flow down.
Least privilegeGrant the narrowest role at the lowest scope, prefer groups over direct user grants, and review unused permissions with IAM Access Analyzer, Microsoft Entra access reviews or the GCP IAM recommender.
Native security servicesAWS: GuardDuty, Security Hub and Security Hub CSPM, IAM Access Analyzer, Config. Azure: Microsoft Defender for Cloud, Microsoft Sentinel, Entra ID Protection. GCP: Security Command Center, Cloud Asset Inventory, IAM recommender.

Authorized use only: run these commands against accounts you administer or have written permission to audit. Most are read only, but they still appear in the audit logs under your identity.

Tip: attackers often turn logging off before they act. Alert on StopLogging, DeleteTrail and UpdateTrail in CloudTrail, on deleted diagnostic settings in the Azure Activity log, and on DeleteSink or UpdateSink in GCP Admin Activity logs.

Hardening Checklist

A baseline per provider. Benchmark against the CIS Foundations Benchmarks for AWS, Azure and GCP.

AWS

  • Use AWS Organizations with separate accounts for workloads, security tooling and log archive, and apply service control policies.
  • Protect the root user with MFA, delete root access keys, and enable centralized root access management where available.
  • Give people access through IAM Identity Center with MFA instead of IAM users and access keys.
  • Run an organization CloudTrail trail in every region with log file validation, delivered to a locked bucket in the log archive account.
  • Turn on S3 Block Public Access at the account level and default encryption with KMS where required.
  • Enable GuardDuty, Security Hub CSPM standards, IAM Access Analyzer and AWS Config in every region through delegated administrators.
  • Require IMDSv2, turn on EBS encryption by default and keep security groups free of 0.0.0.0/0 on management ports.

Microsoft Azure

  • Require MFA for every user with Conditional Access (or security defaults on small tenants) and block legacy authentication.
  • Keep two cloud only break glass accounts with phishing resistant credentials, excluded from risky policies and monitored for sign-ins.
  • Use Privileged Identity Management so Global Administrator, Owner and User Access Administrator are eligible, time bound and approved.
  • Send the Activity log, Entra ID sign-in and audit logs to Log Analytics or Microsoft Sentinel with retention that meets policy.
  • Enable Microsoft Defender for Cloud plans on every subscription and work the secure score recommendations.
  • Disable anonymous blob access and shared key authorization on storage accounts, and enable purge protection on key vaults.
  • Restrict user consent to verified publishers or low risk permissions and review enterprise application grants.

Google Cloud

  • Manage identities in Cloud Identity or Google Workspace and enforce 2-Step Verification, with security keys for admins.
  • Avoid the basic Owner, Editor and Viewer roles; grant predefined or custom roles to groups at the lowest folder or project.
  • Enforce organization policies: disable service account key creation, enforce public access prevention, restrict domain sharing and require uniform bucket level access.
  • Enable Data Access audit logs for sensitive services and route all audit logs to a central, locked log bucket or BigQuery dataset.
  • Activate Security Command Center at the organization level and review findings weekly.
  • Use workload identity federation for external workloads and IAP instead of public SSH and RDP.
  • Act on IAM recommender findings to remove permissions that have not been used in 90 days.
