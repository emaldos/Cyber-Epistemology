Display and Capture Filters

Two different languages: capture filters decide what is saved, display filters decide what is shown.

Capture filterBPF (libpcap) syntax, set before the capture starts in the capture options or with -f. Dropped packets are gone for good, so keep these broad.
Display filterWireshark field syntax such as tcp.port == 443, typed in the filter bar or passed with -Y. Applied to saved packets and changeable at any time.
Building filtersRight click any field in the packet details and choose Apply as Filter or Prepare as Filter. The status bar shows the field name of the selected item.
Field referenceEvery field is listed in the display filter reference at wireshark.org/docs/dfref, or locally with tshark -G fields.
Capture filter (BPF)What it captures
host 10.0.0.5Traffic to or from one host
src host 10.0.0.5Traffic sent by one host only
net 10.0.0.0/24Traffic to or from a subnet
port 53TCP and UDP on port 53
tcp port 443TCP on port 443 only
portrange 8000-8100Any port in a range
not port 22Everything except SSH, useful when capturing over your own SSH session
host 10.0.0.5 and not (port 22 or port 3389)One host without remote admin noise
tcp[tcpflags] & (tcp-syn|tcp-ack) == tcp-synOnly SYN packets, a light way to log connection attempts
tcp[tcpflags] & tcp-rst != 0Only TCP resets
ether host 00:11:22:33:44:55Traffic to or from one MAC address
udp port 67 or udp port 68DHCP only
icmp or icmp6ICMP for IPv4 and IPv6
vlan and host 10.0.0.5One host on a VLAN tagged trunk (vlan must come first)

Tip: when unsure, capture everything into a ring buffer and narrow down later with display filters. A capture filter mistake cannot be undone.

Operators and Syntax

Comparison, logic, sets, slices and functions in the Wireshark 4.x display filter language.

FilterWhat it shows

frame.len > 1000Greater than; also <, >=, <= or gt, lt, ge, le

tcp.port in {8000..8100}Range inside a set
http.host contains "example"Substring match, case sensitive
http.user_agent matches "(curl|wget|python)"PCRE2 regular expression, case insensitive by default (start with (?-i) to make it case sensitive)
eth.src[0:3] == 00:0c:29Slice: first 3 bytes of the source MAC, here a VMware OUI
len(http.request.uri) > 200Function: length of a field, here very long URLs

Handshakes, resets and the expert analysis flags that point to loss, delay or broken connections.

tcp.completeness == 1Streams where only a SYN was seen: no answer, so a filtered port or a dead host
tcp.analysis.flagsEvery packet with a TCP expert warning

tcp.analysis.retransmissionRetransmitted segments: loss or congestion
tcp.analysis.fast_retransmissionRetransmissions triggered by duplicate ACKs

tcp.analysis.lost_segmentGaps in sequence numbers, often packets lost before the capture point

Decrypt TLS you control: set the SSLKEYLOGFILE environment variable before starting a browser, then point Edit, Preferences, Protocols, TLS, (Pre)-Master-Secret log filename at that file. Decrypted traffic appears as http and http2.

Warning: capture only on networks you own or are authorized to monitor. Packet captures can hold passwords and personal data, so store them encrypted and delete them when the case closes.

tshark Command Line

The command line version of Wireshark, for servers, scripts and large files. The same display filters work with -Y.

CommandWhat it does
tshark -DList capture interfaces
tshark -i eth0 -f "not port 22" -w capture.pcapngCapture to a file with a capture filter
tshark -i eth0 -b duration:3600 -b files:24 -w hourly.pcapngRing buffer: a new file every hour, keep the last 24
dumpcap -i eth0 -w capture.pcapngCapture only, with lower overhead for long captures
tshark -r capture.pcapng -Y "http.request" -T fields -e ip.src -e http.host -e http.request.uriPrint chosen fields for matching packets
tshark -r capture.pcapng -Y "tls.handshake.type == 1" -T fields -e tls.handshake.extensions_server_name | sort | uniq -c | sort -rnMost contacted TLS server names
tshark -r capture.pcapng -Y "dns.flags.response == 0" -T fields -E separator=, -e frame.time -e ip.src -e dns.qry.nameDNS queries as CSV
tshark -r capture.pcapng -Y "smb2 || kerberos" -w subset.pcapngSave only matching packets to a new file
tshark -r capture.pcapng -q -z io,phsProtocol hierarchy
tshark -r capture.pcapng -q -z conv,tcpTCP conversations with bytes and duration
tshark -r capture.pcapng -q -z endpoints,ipTop talkers by IP
tshark -r capture.pcapng -q -z http,treeHTTP request and response statistics
tshark -r capture.pcapng -q -z dns,treeDNS statistics by query type and response code
tshark -r capture.pcapng -q -z expertExpert information summary
tshark -r capture.pcapng -q -z credentialsCredentials found in the capture
tshark -r capture.pcapng -q -z follow,tcp,ascii,0Print TCP stream 0 as text
tshark -r capture.pcapng --export-objects http,exportedExtract files transferred over HTTP into a folder (also smb, tftp, imf)
tshark -r capture.pcapng -o tls.keylog_file:sslkeys.log -Y httpDecrypt TLS with a key log file
tshark -G fieldsDump every display filter field name
capinfos capture.pcapngFile summary: packet count, duration, start and end time
mergecap -w merged.pcapng first.pcapng second.pcapngMerge captures in time order
editcap -c 100000 large.pcapng part.pcapngSplit a large capture into files of 100,000 packets
